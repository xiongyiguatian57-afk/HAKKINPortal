SYSTEM OVERVIEW

白金ブランド 勝ち負け表システム 生産計画における需要と供給の過不足を可視化する統合ワークフロー

本資料は、Excel／CSV の需要・供給・在庫データを取り込み、 ペットネーム（品名）別×月別に「手配過不足」を自動計算・可視化する 社内システムの全体像を、初めてご覧になる方向けにまとめたものです。

■ 対象 : 生産管理／営業／販売計画担当
■ 構成 : AgentDBワークスペース + 単独HTML版
■ 版 : 2026-10-15 現在

01

このシステムが解決すること

— WHY —

「いつ・どの品番で・どれだけ足りないのか」を、担当者が Excel を手作業で突き合わせる前に、 一枚のピボット表とダッシュボードで示します。

⚠ 従来の課題
  • 需要と供給のExcelが別ファイル
  • 品名の表記ゆれ（全角半角、スペース）
  • 在庫を手で加算する手間
  • 月をまたぐ累計計算が属人的
✓ 本システムの解決
  • ファイルをドラッグするだけで取込
  • 表記ゆれを自動吸収
  • 在庫を自動で累計起点に加算
  • 月次・累計・不足を自動算出
◎ アウトプット
  • 勝ち負け表（画面＋Excel 3シート）
  • 在庫過不足ダッシュボード
  • 不足TOP品目リスト
  • 月別・累計トレンドチャート
ひとことで言うと 「需要・供給・在庫の3種のExcelを放り込めば、品名のゆれを吸収したうえで、 品番×月の過不足マトリクスとダッシュボードが完成する」ツールです。
02

全体アーキテクチャ

— WHAT —

システムの3層構成

① 入力層

Excel / CSV

需要・供給・在庫の3種のファイルを、ファイル形式から自動判定して取り込みます。

② 処理層

正規化 → 集計 → 判定

品名表記ゆれを吸収、月次集計、累計計算、過不足判定までを一気通貫で実行。

③ 出力層

画面・Excel・ダッシュボード

そのまま社内で共有できる Excel 帳票と、意思決定用のダッシュボードを提供。

03

業務フロー

— HOW —

日常の運用フロー

各ステップの詳細

ファイルを準備する

販売計画チームから「需要」、生産チームから「供給」、資材から「在庫」の Excel/CSV を収集。 ファイル形式は従来の社内フォーマットそのままで OK。

データアップロード画面にドラッグ&ドロップ

ファイル種別は中身から自動判定。シート名（needs / ピボット / 在庫pivot）やヘッダ構造で見分けます。 同じ種別の新ファイルを入れると、過去分は履歴として残しつつ「無効化」できます。

勝ち負け表画面で結果を確認

期間を選び、ペットネーム×月のピボット表を表示。 不足行は赤くハイライト。「不足のみ表示」で絞り込みも可能。

在庫過不足ダッシュボードで俯瞰

KPI（対象品目／不足品目／充足率など）、月別チャート、不足TOP15、累計推移を一画面で確認。 経営・部門長への状況報告に最適。

Excel で配布

社内配布用のリファレンス書式（游ゴシック、罫線、色付き）に沿った3シート構成の Excel を 1クリックで生成。 そのまま印刷・メール添付が可能。

05

データモデル

— DATA —

データは 縦持ち（long形式） で保持されます。1行＝「ある品名のある月の数量」です。 表計算で見慣れた横持ちピボット表は、表示時にシステムが生成します。

テーブル一覧

テーブル役割主なカラム
upload_history アップロード履歴（有効/無効管理） file_type / file_name / uploaded_at / is_active
demand 需要（縦持ち：品名×月） pet_name / period_month / demand_qty / upload_id
supply 供給（縦持ち：品名×月） pet_name / period_month / supply_qty / upload_id
stock 在庫マスタ（累計計算のスタート値） pet_name / stock_qty / upload_id
v_win_loss 勝ち負け集計ビュー（計算結果） pet_name / period_month / demand/supply/stock_qty / 累計 / shortage

データの関係図

ポイント：縦持ち設計の利点 1行の形式が3種で統一されるため、月数が増えても列が増えません。横ピボットは必要なときだけビュー側で動的に組み立てます。
06

計算ロジックの中身

— LOGIC —

核となる1つの式

SHORTAGE FORMULA
手配過不足 = MAX ( 0 ,  需要累計 − ( 在庫 + 供給累計 ) )
マイナス（余剰）は 0 にクランプして「不足のみ」を数値化します

3つの前処理

① ペットネーム正規化

表記ゆれ吸収

  • 全角英数 → 半角
  • 全角/半角スペース → 削除
  • 大文字化

例：「Platinum A」「ＰＬＡＴＩＮＵＭ-A」「 platinumA 」はすべて同一品目として扱う

② 月ヘッダ年跨ぎ判定

「7月」形式の翻年

供給ファイルの月ヘッダに年がない場合（例：「7月」のみ）、 需要側の最小月を基準に、順に進める方向で年を推定。

例：需要最小=2026/09 → 「7月」は 2027/07 とみなす

③ 在庫の累計起点加算

先頭月に+加算

在庫は供給の累計計算のスタート値として、 対象期間の先頭月に1回だけ加算されます（二重計上を防止）。

有効/無効フラグによる履歴管理

同じ種別のファイルをアップロードし直すと、過去のアップロードは履歴として残しつつ、 集計対象から外せます。古いファイルを有効化し直すことで、過去の計算結果を再現することも可能です。

注意 集計対象は is_active = TRUE のアップロードのみ。 「古いデータが集計に混ざっている」と感じたら、まずアップロード履歴の有効/無効を確認してください。

2つの提供形態

— DEPLOYMENT —
形態特徴保存先想定ユーザー
AgentDBワークスペース版 社内で共通のワークスペース。複数人で同じデータを見られる。アプリ4つで構成。 サーバー側 PostgreSQL 共有運用／部門全体

AgentDB版

  • 勝ち負け表画面
  • 在庫過不足ダッシュボード画面
  • Overview画面

データは AgentDB の PostgreSQL に保存され、同じワークスペースに招待されたメンバー全員で共有できます。

  • 1ファイル（勝ち負け表.html 約83KB）

  • 以降はオフライン動作可能
  • データはそのPCのブラウザ内に保存
  • JSONエクスポート/インポートで他PCへ移行可

Edge / Chrome 推奨。社内配布や個人試算に最適で、サーバー不要。

よくある質問（FAQ 抜粋）

Q. ファイル形式を気にする必要はありますか？

A. 従来の社内フォーマットのままで取り込めます。シート名やヘッダ構造でシステムが自動判別します。

Q. 品名が全く同じでも別物として集計されてしまいます

A. 大半は全角半角・スペース・大文字小文字で自動的に吸収されます。それ以外のゆれ（例：末尾の記号違い）は、 元ファイル側で表記を統一してください。

Q. 間違ったファイルを上げてしまいました

A. アップロード画面の履歴から「無効化」または「削除」で取り消せます。無効化しても元データは残るので、 後から「やっぱり有効化」も可能です。

Q. 複数のPCで同じデータを使えますか？

A. AgentDB版なら同じワークスペースに招待されたメンバー全員で共有できます。 デスクトップ版は個別ブラウザに保存されるため、JSONエクスポート/インポートで移行してください。

主な実装上の工夫（技術的トピック）

  • タイムゾーン問題の回避：Excel出力時の月ヘッダがUTC変換で1ヶ月前にずれる既知の問題を、Date.UTC() ベースの日付生成で解消。
  • ペット正規化のビュー実装：関数作成が許可されない制約のため、v_win_loss ビュー内に正規化式を直接埋め込み。
  • デスクトップ版のゼロ構築：Dexie.js(IndexedDB)、xlsx.js、ExcelJS、Chart.js をCDN経由で読み込み、初回ロード後はオフライン動作。
