# 工程計画検索システム — Google Apps Script デプロイ手順 (v2)

> **v2の変更点**: 管理者判定を Gmailログイン方式(`ADMIN_EMAIL`)から **管理者パスワード方式(`ADMIN_PASSWORD`)** に変更しました。
> Webアプリ公開設定が「全員」の場合、Googleの仕様で `Session.getActiveUser()` が空になるため、Gmail判定ができなかった問題を解消しています。

## デプロイ手順(初回のみ・所要時間 約15分)

### 【1】 Apps Scriptプロジェクトを作成する

1. 管理者Gmailアカウントで https://script.google.com/ を開く
2. 左上「＋ 新しいプロジェクト」をクリック
3. 上部の「無題のプロジェクト」を **「工程計画検索」** に変更

### 【2】 ファイルを7つ用意する

Apps Scriptエディタの左サイドバーで、以下のファイルを作成し、この納品物の同名ファイルの中身を貼り付けます。

| Apps Script側での作成手順 | 貼り付ける中身 |
|---|---|
| デフォルトで存在する `Code.gs` を開く | `Code.gs` |
| 「＋」→ HTML → **`Index`** で作成 | `Index.html` |
| 「＋」→ HTML → **`Admin`** で作成 | `Admin.html` |
| 「＋」→ HTML → **`Core`** で作成 | `Core.html` |
| 「＋」→ HTML → **`Style`** で作成 | `Style.html` |
| 左サイドバー ⚙️「プロジェクトの設定」→ 「`appsscript.json` マニフェスト ファイルをエディタで表示する」に✓ を入れる → 出現した `appsscript.json` を開く | `appsscript.json` |

> ※ Apps Scriptでは、HTMLファイルを作るときに拡張子 `.html` を入力しないでください(自動で付きます)。

すべて貼り付けたら 💾 保存(Ctrl+S)。

### 【3】 スクリプトプロパティ(3件)を設定する

左サイドバー ⚙️「プロジェクトの設定」→ 下部「スクリプト プロパティ」→ 「スクリプト プロパティを追加」で以下3件を登録:

| プロパティ名 | 値 | 説明 |
|---|---|---|
| `VIEWER_PASSWORD` | (任意の閲覧パスワード) | 例: `kotei2026`。一般ユーザーが入力する |
| `ADMIN_PASSWORD` | (任意の管理者パスワード) | 例: `admin2026`。管理者URLで入力する / **必ず閲覧用と別の値にする** |
| `DATA_FILE_ID` | (空欄でOK) | 次のステップで自動作成される |

> ⚠️ **v2重要変更**: Webアプリを「全員」公開にしているため、Google の仕様上サーバー側からログインユーザーを識別できません。従来の `ADMIN_EMAIL`(Gmailログイン判定)では管理者を判別できないため、**管理者パスワード方式** に変更しました。

「スクリプト プロパティを保存」をクリック。

### 【4】 データファイル(data.json)を初期化する

Apps Scriptエディタ上部の関数選択プルダウンで **`setupInitialData`** を選択 →「▶実行」をクリック。

- 初回のみ「承認が必要です」→「権限を確認」→ 管理者Gmail選択 → 「詳細」→「(安全でないページに移動)」→「許可」
- 実行ログに `data.json を作成しました。fileId=XXXXXXXX...` と表示される
- そのfileIDをコピーし、⚙️「プロジェクトの設定」→「スクリプト プロパティ」の `DATA_FILE_ID` に貼り付け → 保存

### 【5】 Web App としてデプロイする

1. 右上「デプロイ」→「新しいデプロイ」
2. 種類の選択(⚙️)→ **「ウェブアプリ」**
3. 以下を入力:
   - 説明: `工程計画検索 v1`
   - 次のユーザーとして実行: **自分(管理者Gmail)**
   - アクセスできるユーザー: **全員** ← ここが重要
4. 「デプロイ」→ **URLをコピー**

このURLが 👉 **一般ユーザー用URL** です。
末尾に `?admin=1` を付けたURLが 👉 **管理者用URL** です。

例:
```
一般ユーザー: https://script.google.com/macros/s/AKfycb.../exec
管理者     : https://script.google.com/macros/s/AKfycb.../exec?admin=1
```

### 【6】 管理者URLでログインしてデータを投入する

1. **管理者URL** (`.../exec?admin=1`) を開く
2. ブラウザのプロンプトが表示される → **管理者パスワード** (`ADMIN_PASSWORD` に設定した値) を入力
3. 上部に「ログイン中: 管理者 (パスワード認証済み)」と表示されることを確認
4. 「データを更新する」パネルで:
   - 左に **受注データ(csv/xls)** を投入
   - 右に **型番マスタ(xlsx)** を投入
   - 「取り込み実行」をクリック → 内部データが更新される
   - **「💾 Google Driveに保存」** をクリック → data.json に反映
5. 一般ユーザー用URLを別ブラウザまたはシークレットウィンドウで開き、閲覧パスワード入力 → データが見えることを確認

## 運用手順(定期更新のたび)

管理者は以下の3ステップだけで済みます:

1. 管理者URL(`.../exec?admin=1`)を開く → 管理者パスワードを入力
2. 新しい受注csvまたは型番マスタxlsxをドラッグ&ドロップ → 「取り込み実行」
3. **「💾 Google Driveに保存」** をクリック

一般ユーザーは次回ブラウザリロードで新データを見られます。

## 更新・パスワード変更

- **閲覧パスワード変更**: ⚙️「プロジェクトの設定」→ スクリプトプロパティの `VIEWER_PASSWORD` を書き換えるだけ
- **管理者パスワード変更**: 同じく `ADMIN_PASSWORD` を書き換える
- **コード修正時**: エディタで編集 → 保存 → 「デプロイ」→ 「デプロイを管理」→ 「編集」(鉛筆マーク)→ バージョン「新しいバージョン」→ 「デプロイ」
  - ※ **URLは変わりません**
- **管理者を交代する場合**: Apps Scriptプロジェクトの共有権限を新管理者に付与 + `ADMIN_PASSWORD` を新管理者に伝える

## トラブルシューティング

| 症状 | 対処 |
|---|---|
| 一般ユーザー画面で「パスワードが違います」と出続ける | ⚙️「スクリプトプロパティ」の `VIEWER_PASSWORD` を確認 |
| 管理者画面で「管理者パスワードが違います」 | ⚙️「スクリプトプロパティ」の `ADMIN_PASSWORD` を確認 |
| 「data.json のファイルIDがサーバーに設定されていません」 | `DATA_FILE_ID` プロパティが空。 手順【4】を再実行 |
| Chromeで「アドレスを確認してもう一度お試しください」 | Chromeのサードパーティ Cookie 制限が原因。 `chrome://settings/cookies` → 「常に使用できるサイト」に `[*.]google.com` と `[*.]googleusercontent.com` を追加。または Edge で開く |
| 「Googleによって確認されていません」警告 | 一般ユーザー画面にはこの警告は出ない設計だが、もし出たら「詳細」→「(安全でないページに移動)」で通過 |
| 保存時 "Timeout" | データが100MB超の可能性。 受注データを絞ってください(通常1万件程度なら数MBで収まる) |
| 一日の実行回数上限に達した | 個人Gmailは 20,000回/日、90分/日 まで。 通常運用では枯渇しません |

## セキュリティ設計メモ

- 一般ユーザー画面はGoogleログイン不要だが、必ずパスワード認証を通過しないと `loadData` が拒否される
- パスワードはコードに埋め込まず、スクリプトプロパティ(サーバー側)に保管
- 閲覧トークンはSHA256+ソルトのハッシュとしてブラウザに保存(30日)、URLに漏れない
- 管理者操作(`saveData`)は **管理者パスワード(ADMIN_PASSWORD)** で毎回サーバー側検証 → 一般ユーザーが管理者URLを開いても、パスワードを知らなければ保存操作は不可能
- 閲覧用と管理者用のパスワードは **必ず別のものにする** こと(同じにするとURLが漏れた時に一気に管理者権限まで奪われる)
